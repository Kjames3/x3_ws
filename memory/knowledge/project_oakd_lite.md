`src/oakd_camera_viewer.py` (laptop, not Jetson) shows OAK-D Lite left/right stereo, depth, IMU, and color windows with resolution/FPS overlays. depthai 2.32, device MxId 1944301081C69F5A00.

**Known-good config (2026-07-09):** USB_SPEED="SUPER" (USB3) works only on the correct USB3 port + a real USB3.2 cable; 4K color crashed/failed to stream, **1080P color works fine**. USB2 fallback is USB_SPEED="HIGH" — use it if the firmware throws `errorId 9001 "Device has crashed" / Input/output error` (a power/signal-integrity issue on the Lite, not a code bug). Color streams via an on-device MJPEG VideoEncoder (decoded host-side with cv2.imdecode) so high-res fits the link.

**Perf ceiling:** all streams converge ~22-29 FPS and IMU ~180 Hz because the single-threaded viewer loop (MJPEG decode + 5x imshow + waitKey) caps loop rate, not USB/sensors. Sensors have headroom (stereo 117 FPS, IMU 400-500 Hz configured).

**On robot (2026-07-10):** OAK-D Lite is now physically mounted on the robot (URDF: `oak-d-base-frame` + full depthai optical frames at base_link x=0.0435,z=0.185; lidar moved 55mm back/6mm up). `depthai 2.32.0.0` installed on jetson via `python3 -m pip install --user "depthai<3"` (v2 API — the viewer + driver use XLinkOut/getOutputQueue; v3 would break them). **udev rule REQUIRED** and needs sudo (user runs it): `echo 'SUBSYSTEM=="usb", ATTRS{idVendor}=="03e7", MODE="0666"' | sudo tee /etc/udev/rules.d/80-movidius.rules && sudo udevadm control --reload-rules && sudo udevadm trigger`, then replug. Without it: `Insufficient permissions ... Failed to boot device`. Device enumerates as `03e7:2485` (bootloader).

**Wired into server (2026-07-10):** new `src/oakd_driver.py` = headless `OakDCamera` (mono L/R + on-device StereoDepth + BMI270 IMU, NO color — Astra keeps RGB). Exposes AstraCamera/ROS2Bridge-compatible depth API (`get_depth_frame`/`get_raw_depth_frame`/`get_depth_frame_age`) + `get_stereo_frames()`/`get_imu()`; runs a background thread with reconnect/backoff, degrades gracefully if absent. In `server_x3.py`: constructed in `initialize_hardware()` (global `oak`), becomes the **depth source** for broadcast_loop (falls back to orbbec/Astra when `oak.available` is False) and VelocityEstimator; readout gains `oak_imu` (always) + `oak_left`/`oak_right` (base64, gated by new `toggle_stereo`, default off); `--no-oak` flag disables. Deployed + compiles on robot; **service NOT yet restarted** (waiting on udev rule). GUI (main.js/GUI.html) not yet updated to render stereo/imu.

**Spatial detection (2026-07-11):** blob delivered as a Luxonis `.superblob` (RVC2, NN-archive: superblob+config.json+buildinfo.json). depthai 2.32 CANNOT load a superblob (no `dai.OpenVINO.SuperBlob`), and it's not a plain blob. Carve the base blob out with `src/blobs/extract_superblob.py`: superblob = 136-byte BIG-ENDIAN header (int64 blobSize + 16 int64 patchSizes) + base blob + patches; base = bytes[136:136+blobSize] = the 8-shave `yolo26n.blob` (input `images` 480x640x3 U8, output `output_yolo26` [85,6300] FP16). **depthai v2 on-device `YoloSpatialDetectionNetwork` CANNOT decode the yolo26 head** — it floods `"Mask is not defined for output layer with width '85' ... setAnchorMasks for 'side85'"` every frame, pegging the host CPU (→ ~5fps camera, and enabling CPU-YOLO detection then froze the whole async server). Fix: run the blob as a plain `dai.node.NeuralNetwork` and decode `[85,6300]` (4 box + 1 obj + 80 cls, 6300 anchors for strides 8/16/32 @480x640) in host numpy (sigmoid-if-logits, NMS in `oakd_driver._process_nn`), with XYZ from the CAM_A-aligned depth (`setDepthAlign(CAM_A)`, `setOutputSize(480,640)`, intrinsics via `readCalibration`). Box-coord convention (normalised vs pixel) is auto-detected + logged once as "OAK NN probe:" — VERIFY that log line after restart to confirm decode. Also fixed two CPU wasters in the driver: busy-poll loop → block on depth queue; depth colourised lazily in `get_depth_frame()` instead of every 30fps frame.

**Detections working (2026-07-11):** locked decode mode `('am', False)` — yolo26 output is anchor-major [6300,85], box cxcywh(px) at 0:3, 80 class scores at 4:83, ch84 unused, NO objectness; score=max(cls). Person detected on both stereo cams. CRITICAL BUG fixed: detection XYZ used `round(np.float64,3)` → `TypeError: Type is not JSON serializable: numpy.float64` crashed the readout broadcast → systemd crash-loop (that was the "works 5s then freezes"); `_locate` now returns native `float()`. Any numpy scalar in a readout field crashes orjson/json — always cast to python float/int.

**USB2 root cause = FAILING CABLE (2026-07-11/12):** the bundled USB-C cable has ONE dead SuperSpeed lane-set — it enumerated at USB2 ("HIGH") on BOTH the Jetson and the laptop (even the bootloader showed `speed=480` in sysfs, before software), and threw `Input/output error` after one connect on USB2.
