# Offline filter evaluation

Ten raised-box frames (indices 0,6,...54). Calibration taken from each pair,
nominal RGB rectification via c1_dataset; current MxId correction exactly once.
No runtime changes/deployment. Measurements from robot-side offline processing.

Fixed RGB ROI x136..249,y149..317. Interior inset4px. Border is the remaining4px
ring, NOT a semantic orange-pixel segmentation. Spill proxy is corrected depth
within100mm of1.24m, outside RGB ROI, inside x116..269,y129..307. Bottom support
excluded. Straps can be legitimate geometry in this proxy; it is not ground-truth
miscoloring precision. Ratios pooled over valid pixel counts across ten frames.

Timings exclude RGB rectification, transport, serialization and browser work;
these are ten samples, not acceptance performance measurements. The0px case
still rejects immediate discontinuities; it is not a completely unfiltered cloud.

Inspect cloud-detail.png, generated by src/tools/perception/oak_color_cloud_plot.py.
This reprojects the actual6000-point budgeted cloud from one frame into the camera
view, with no temporal accumulation/interpolation. The purple surface survives,
but the orange outline and printed detail become sparse. The global row-major
linspace sampler also leaves a visible sampling pattern. This is insufficient
proof of useful recognizability and not ready for live deployment.

Next proposed experiment: retain uncertain geometry as neutral points and apply
RGB only where confidence supports it; use spatially balanced sampling. Keep
this offline and compare identical point budgets before asking to increase point
count or bandwidth. This is a proposal, not an implemented/validated fix.
No calibration shifts fitted; full image registration gate remains unqualified.
